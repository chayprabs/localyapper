# Architecture

LocalYapper is a Tauri 2 app: a Rust back end that owns everything that
happens during a dictation, and two web pages, the settings window
(React) and the overlay pill (plain TypeScript).

## Dictation path

```
hotkey ─► controller ─► audio thread (cpal) ─► ring buffer ─► segmenter (Silero VAD)
                                                               │ closed segments
                                                               ▼
target app ◄─ inject (clipboard save/set/paste/restore) ◄─ controller ◄─ STT worker (sherpa-onnx)
```

1. **Hotkey** (`platform/hotkey`). The global-shortcut plugin on Windows,
   macOS and X11 (with an X11 auto-repeat filter, `repeat_filter.rs`), or
   the GlobalShortcuts portal on Wayland. Presses and releases become
   `Event::RecordDown` / `RecordUp` for the controller.
2. **Controller** (`controller.rs`). One tokio task that owns the
   dictation state machine (`core/session.rs`) and executes its effects in
   order: start or stop capture, load the model, show the overlay, set
   the tray, play cues, register the cancel key, paste, save history,
   schedule eviction. Nothing else changes dictation state.
3. **Audio** (`platform/audio_in.rs`). A long-lived audio thread owns the
   cpal stream, which is built on press. Samples go through a lock-free
   ring buffer (`ringbuf`); audio stays in memory.
4. **Segmenter** (`core/audio/segmenter.rs`). One thread per recording:
   resamples to 16 kHz, runs Silero VAD (energy detector as fallback),
   reports the level to the overlay, and hands each closed speech segment
   to the STT worker while the user is still talking. A rolling buffer
   (`core/audio/rolling.rs`) keeps the pre-roll.
5. **STT worker** (`core/stt/manager.rs`, `engine.rs`). Loads the model on
   the first press (in parallel with recording), decodes segments in
   order and reports text per segment. After the idle time the model is
   dropped and `mi_collect` returns the memory to the OS.
6. **Inject** (`platform/inject`). Saves the clipboard, sets the text,
   sends the paste keys to the window that was in front when recording
   started, and restores the clipboard after a delay. Per-OS key paths
   live in `windows.rs`, `macos.rs` and `linux.rs` (X11, or wtype/ydotool
   on Wayland). `paste_method` picks Ctrl+V, Ctrl+Shift+V, Shift+Insert,
   typing, or copy only.

Stage timings for each dictation are logged (`dictation: ...`) and kept
for diagnostics; they never include text.

## Windows

- **Overlay** (`platform/overlay`, `overlay.html`). Created hidden at
  start so a key press never waits for a WebView. Non-activating on
  every OS (an NSPanel on macOS): clicking or dragging the pill never
  moves keyboard focus. The pill can be dragged; the page reports press,
  move and release (`overlay_drag`), Rust moves the window with the real
  cursor position and saves the spot as the custom overlay position. All
  window geometry work runs on the main thread.
- **Settings window** (`index.html`, `src/`). Built on demand (tray,
  open-app key, second launch, first-run wizard), destroyed on close,
  never built when the OS starts the app at login.

## Settings

`settings/keys.rs` lists every key with its type, default, validator and
hook. `set_setting` validates, stores in SQLite, updates the in-memory
cache that hot paths read, runs the key's hook (reload the controller,
re-register hotkeys with rollback, launch at login, theme, evict the
model, prune history) and emits `settings-changed`. Schema migrations use
`PRAGMA user_version` (`db/schema.rs`).

## Models

`src-tauri/models.json` pins each model's files, sizes and SHA-256
(generated by `scripts/gen-model-manifest.py`). `core/download.rs`
resumes partial downloads, verifies every file and writes a `.verified`
marker; only verified models are offered. Waits are timed, a dropped
connection is retried from the part file, and `commands/models.rs` runs
one download at a time, each with its own cancel flag. `core/stt/catalog.rs` resolves
`auto` to Parakeet 110M, or Moonshine Tiny under 6 GB of RAM.

## Data

SQLite (`rusqlite`, bundled) in the app data folder holds two tables,
`transcription_history` and `settings`. Logs go to the app log folder
(two files of at most 1 MB). Models live in `models/<id>` under the data
folder.

## Tests

- Unit tests next to the code, including one hook test per setting.
- `tests/pipeline.rs`: fixture audio through the segmenter and model,
  word error rate against the reference text.
- `tests/fresh_install.rs`: an empty profile downloads, verifies and
  dictates.
- `tests/smoke.rs`: the real app on each OS, driven by a local control
  channel that only exists with the `test-hooks` feature.
